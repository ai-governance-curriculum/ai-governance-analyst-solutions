# Exercise 04 — GenAI Profile Risks Mapped to Use Cases — Reference Solution

## 1. Solution overview

NIST **AI 600-1: Artificial Intelligence Risk Management Framework —
Generative Artificial Intelligence Profile** (July 2024) extends NIST AI RMF
1.0 with a list of twelve risks that are either unique to generative AI or
materially amplified by it. The profile also maps each risk to RMF actions
across the Govern / Map / Measure / Manage functions.

The analyst's task in this exercise is to pick a representative set of
generative-AI use cases and show which of the twelve risks each one raises,
how it manifests in practice, and which RMF actions should be prioritised.

This solution provides:

- A reference listing of the twelve risks with one-line definitions.
- A worked mapping across five canonical use cases.
- Decision rationale for the mappings.
- A rubric for grading a learner's mapping.

## 2. Worked answer or implementation

### 2.1 The twelve GenAI risks (AI 600-1)

| # | Risk | One-line definition |
| --- | --- | --- |
| 1 | CBRN information or capabilities | Lowered barriers to creating or accessing chemical, biological, radiological, or nuclear weapon design or synthesis information. |
| 2 | Confabulation | Model output that is confidently stated and appears coherent but is factually incorrect or unfounded (often called "hallucination"). |
| 3 | Dangerous, violent, or hateful content | Generation of content that incites violence, hate, or self-harm, including calls to action against individuals or groups. |
| 4 | Data privacy | Leakage, inference, or memorisation of personal data; privacy harms via training data, prompts, or outputs. |
| 5 | Environmental impacts | Energy, water, and material footprint of training and inference, and the downstream environmental consequences. |
| 6 | Harmful bias and homogenisation | Output that systematically disadvantages groups, or that collapses diverse inputs toward a narrower set of outputs. |
| 7 | Human–AI configuration | Over-reliance, under-reliance, misuse, or inappropriate anthropomorphism in how humans interact with the system. |
| 8 | Information integrity | Degradation of the information environment via plausible but unreliable or manipulated content at scale. |
| 9 | Information security | New attack surface: prompt injection, model/data exfiltration, insecure plug-in and tool execution, agentic autonomy misuse. |
| 10 | Intellectual property | Reproduction, unauthorised use, or uncertain ownership of training material or generated outputs. |
| 11 | Obscene, degrading, and/or abusive content | Non-consensual intimate imagery, CSAM, and related categories generated by the model. |
| 12 | Value chain and component integration | Risk that propagates through the supply chain of models, data, tools, and deployers — including third-party model use. |

### 2.2 Worked mapping — five canonical use cases

Legend for RMF action columns: **G**overn, **M**ap, **Me**asure, **Mn**
Manage. Priority = analyst's estimate of how load-bearing that risk is for
this use case (H / M / L).

#### Case 1 — Internal RAG assistant over company policy documents

| Risk | Manifestation in this use case | Priority | Key RMF actions |
| --- | --- | --- | --- |
| Confabulation | Assistant invents a policy clause or citation that sounds authoritative. | **H** | M: capture ground-truth corpus; Me: factuality eval with policy-anchored tests; Mn: show citations and route unresolved questions to humans. |
| Data privacy | Confidential HR or legal documents surfaced to unauthorised users via retrieval. | **H** | G: access-control policy on the index; M: data classification of sources; Mn: query-time authorisation. |
| Information security | Prompt-injection in retrieved document executes tool calls. | **H** | Me: red-team retrieval with poisoned docs; Mn: tool allowlists, output filtering. |
| Human-AI configuration | Staff treat the assistant as authoritative and skip verification. | M | G: acceptable-use policy; Me: user-comprehension study; Mn: UI framing, disclaimers. |
| Value chain integration | Upstream foundation model changes behaviour after update. | M | G: vendor change-notice SLA; Me: regression evals on version updates. |

#### Case 2 — Customer-facing support chatbot for a regulated service (e.g., banking)

| Risk | Manifestation | Priority | Key RMF actions |
| --- | --- | --- | --- |
| Confabulation | Bot invents fees or product terms, creating consumer-protection exposure. | **H** | Me: scripted factuality tests tied to product catalogue; Mn: constrained generation + canned responses for regulated topics. |
| Harmful bias & homogenisation | Different quality of service by language or dialect. | **H** | Me: segmented eval across languages and demographics. |
| Human-AI configuration | Customers believe they are speaking to a human. | **H** | G: transparency-disclosure policy; Mn: AI-nature disclosure on every session. |
| Information security | Prompt injection via user messages to exfiltrate backend data. | **H** | Me: adversarial prompts in test suite; Mn: tool-access scoping. |
| Information integrity | Bot repeats unverified claims to many customers at once. | M | Me: monitoring of claim frequency; Mn: feedback loop to update canned answers. |

#### Case 3 — Code-generation assistant for internal developers

| Risk | Manifestation | Priority | Key RMF actions |
| --- | --- | --- | --- |
| Intellectual property | Suggestions reproduce copyleft code verbatim. | **H** | G: IP policy on generated code; Me: snippet-match detection in the pipeline. |
| Information security | Suggestions include insecure patterns (SQLi, path traversal) or hallucinated package names (slopsquatting). | **H** | Me: SAST and dependency checks in CI; Mn: curated package allowlist. |
| Confabulation | Invented APIs, function signatures, or configuration keys. | M | Me: build-time tests; Mn: linting against actual SDKs. |
| Data privacy | Developers paste confidential code into prompts to a hosted model. | **H** | G: data-handling policy; Mn: enterprise tenancy + prompt redaction. |
| Value chain integration | Model vendor retires or changes the model mid-project. | M | G: vendor-deprecation SLA; Me: eval harness for substitutes. |

#### Case 4 — Marketing-content generator (text and image) for external campaigns

| Risk | Manifestation | Priority | Key RMF actions |
| --- | --- | --- | --- |
| Intellectual property | Generated images imitate a named artist's style; text reproduces trademarked slogans. | **H** | G: brand & IP review gate; Me: style/trademark screens; Mn: pre-publication human review. |
| Harmful bias & homogenisation | Imagery underrepresents or stereotypes demographic groups. | **H** | Me: cohort audit of outputs; Mn: diversity prompts, art-direction guardrails. |
| Information integrity | Synthetic imagery of real events circulates as authentic. | M | Mn: synthetic-media labelling (links to EU AI Act Art. 50 transparency obligation when applicable). |
| Obscene, degrading, abusive content | Users jailbreak to produce non-consensual imagery. | M | G: acceptable-use enforcement; Me: safety-filter eval. |
| Environmental impacts | High-volume image generation increases energy footprint. | L | G: report in sustainability metrics; Mn: batch and cache aggressively. |

#### Case 5 — Agentic assistant that can browse the web and call internal tools

| Risk | Manifestation | Priority | Key RMF actions |
| --- | --- | --- | --- |
| Information security | Prompt injection from web pages triggers unauthorised tool calls. | **H** | Me: adversarial-browsing red team; Mn: tool allowlist, approval-required actions. |
| Human-AI configuration | Operator over-trusts autonomous actions. | **H** | G: autonomy-level policy; Mn: human-in-loop for destructive actions. |
| Confabulation | Agent fabricates intermediate results and continues the plan. | **H** | Me: step-level truth evals; Mn: verification steps before irreversible actions. |
| Data privacy | Agent reads sensitive pages and includes them in prompts to an external model. | **H** | G: egress policy; Mn: redaction before model calls. |
| Value chain integration | Downstream tools and plug-ins become new failure surfaces. | **H** | G: third-party tool onboarding review; Me: tool-level eval. |
| Dangerous, violent, or hateful content | Agent follows adversarial instructions to produce harmful content for a target. | M | Me: safety evals against attacker-controlled web pages. |

### 2.3 Decision rationale

- **Risks chosen per case are the top five or six, not all twelve.** Listing
  all twelve for every case is noise; the drill teaches analysts to
  prioritise. The rubric rewards priority judgement, not completeness.
- **Priority is modality- and surface-driven.** RAG surfaces document
  injection; code gen surfaces IP and insecure patterns; agentic systems
  surface tool-execution risk. Mapping tracks the surface, not just the task.
- **Each risk is paired with an RMF action.** The GenAI Profile's value is
  that it hooks every risk back into Govern / Map / Measure / Manage.
  Mappings without an RMF action teach risk-naming but not risk-management.
- **CBRN and obscene/abusive content appear selectively.** For internal
  productivity tools these are low priority; for consumer-facing image
  models they jump to top-of-list. The mapping respects that asymmetry.
- **Value-chain integration shows up everywhere there is a vendor model.**
  It is the one risk the analyst should always sanity-check, because almost
  every modern deployment inherits a foundation model.

## 3. Validation steps

1. Confirm that the risk list uses the NIST AI 600-1 risk names exactly
   (spelling and casing); analysts often paraphrase them into non-canonical
   forms that are hard to search for later.
2. For each use case, confirm the top-priority risks match the technical
   surface — e.g., retrieval → information security; synthetic media → IP
   and information integrity; agents → tool execution and human–AI
   configuration.
3. Confirm every risk cell has at least one RMF action (one of Govern / Map
   / Measure / Manage).
4. Trace one action per case back to a concrete artefact (eval script,
   policy section, gate). If the action cannot be made concrete, either the
   use case description is too vague or the mapping is aspirational.
5. Cross-check: if the use case would also fall under EU AI Act Article 50
   (synthetic content or chatbot), note that transparency obligation in the
   mapping.

## 4. Rubric or review checklist

Score each use case out of 5; passing average ≥ 3.5.

| Score | Criterion |
| --- | --- |
| **5 — excellent** | Top 5–6 risks named with canonical NIST AI 600-1 terms; priorities justified by the technical surface; every risk has at least one concrete RMF action tied to an artefact. |
| **4 — strong** | Top risks correct; priorities mostly justified; RMF actions present but one or two are generic. |
| **3 — acceptable** | Reasonable risk set; priorities plausible; several RMF actions missing or hand-wavy. |
| **2 — weak** | Risks named but only loosely linked to the use case; priorities not justified; few RMF actions. |
| **1 — poor** | Random risk assignment; no clear action plan. |
| **0 — fail** | Invented risks, or risks that contradict NIST AI 600-1 definitions. |

Deck-level checks:

- [ ] At least one case that drives the five "agent-era" risks (info
      security, value-chain, human-AI configuration, confabulation,
      data privacy).
- [ ] At least one case where IP, information integrity, and bias dominate
      (synthetic media).
- [ ] At least one case touching CBRN or obscene/abusive content so learners
      understand when those categories apply.
- [ ] Every mapping cites an RMF action.
- [ ] No case reuses an identical mapping — the drill fails if different
      technical surfaces produce the same answer.

## 5. Common mistakes

- **Tagging every case with all twelve risks.** It produces a tag cloud, not
  a prioritised map. The exercise teaches judgement about which risks are
  load-bearing.
- **Confusing "confabulation" with "hallucination".** NIST uses
  "confabulation" in AI 600-1. The two terms are interchangeable
  colloquially but using NIST's wording makes downstream search and
  reporting easier.
- **Treating "information integrity" as the same as factual accuracy.**
  Integrity is a societal, information-environment risk; factual accuracy at
  the output level is confabulation. The Profile separates them because the
  mitigations differ.
- **Ignoring the value-chain / component integration risk.** Nearly every
  deployment uses a third-party model; analysts who skip this leave upstream
  change-notice and deprecation risk unmanaged.
- **No RMF action attached.** The Profile exists to bridge risks to the
  RMF Core. A map that only names risks is half the exercise.
- **Mapping risks without reflecting modality.** Text-only and image+text
  and agentic systems have different dominant risks; using the same five
  risks for every case is a sign the learner has not internalised the
  Profile.
